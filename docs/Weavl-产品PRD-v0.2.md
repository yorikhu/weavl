# Weavl 产品设计：创作、Agent、工作流与资产

> 状态：定位与功能讨论稿 · 2026-09-14
> 依据：本轮确定的六项产品构想及当前仓库代码。本文作为后续讨论基线；不代表相关功能已经实现。
> 目标：用一套稳定的资产与能力体系，支持自由创作、对话创作、市场复用和企业工作流交付。

## 1. 产品定义

**Weavl 是一个以资产为连接层的多模态 AIGC 创作与自动化平台。** 用户可以在 Agent 中对话生成，在画布项目中组织和编辑，或者运行工作流完成重复的业务任务；三种方式生成的资产能被彼此引用和继续加工。

首期以个人化 IP 打造验证复杂业务交付，但产品对象不围绕 IP 写死。Word、PPT、PDF、图片、音频、视频、数字人等被视为可扩展的资产类型或生成能力；**支持一种文件进入资产库，与承诺高质量生成或深度编辑该文件，是不同的交付阶段**。

建议对外表达：**“从一个想法到作品，再把有效的方法变成可重复的流程。”** 用户第一次打开产品时应能看懂可做的事，而不必先理解节点、模型供应商或工作流配置。

### 1.1 六个模块的用户价值

| 模块        | 用户要完成的事                               | 与其他模块的关系                                       |
| ----------- | -------------------------------------------- | ------------------------------------------------------ |
| 首页        | 了解能力、看到可信案例、从 Agent 开始        | 导向项目、市场、工作流，不承担创作状态                 |
| 项目＝画布  | 自由组织、预览、编辑和组合内容               | 引用个人、Agent 与工作流资产；可用 Agent 辅助操作      |
| Weavl Agent | 在连续对话中用提示词或 Skill 生成、修改内容  | 独立会话可转成画布项目；产物进入资产库                 |
| 市场        | 发现、使用、创建和管理提示词与 Skill         | 为 Agent、画布和工作流提供可复用方法                   |
| 工作流      | 定义和运行有表单、复杂节点、审核与重试的 SOP | 输入可选资产；阶段与最终产物保存到资产库，按需放进画布 |
| 资产        | 像云盘一样管理文件和结构化产物               | 所有模块共同读写的内容层，可用文件夹组织               |

**本版不再使用“预设”作为产品对象。** 当前代码中的 `TemplateManifest` 在业务上归为工作流定义；提示词和 Skill 留在市场，不与工作流混称。

## 2. 用户与产品边界

| 用户                 | 首要目标                    | 主要入口           | 成功体验                               |
| -------------------- | --------------------------- | ------------------ | -------------------------------------- |
| 初次使用的个人创作者 | 快速得到可编辑内容          | 首页 → Weavl Agent | 一句话开始，能找到历史会话和产物       |
| 设计师、内容制作人   | 组合素材并局部修改          | 项目画布           | 素材可拖入、生成结果能继续调整和导出   |
| IP 服务团队运营者    | 将客户资料变成稳定交付物    | 工作流 WebUI       | 填表、看进度、审核关键产物、重试、交付 |
| 流程设计者           | 把团队 SOP 做成可复用工作流 | 工作流编排器       | 节点和字段可配置、可测试、可发布版本   |
| Skill／提示词作者    | 沉淀自己的方法              | 市场 → 我的创作    | 可创建、试用、更新、私有使用或申请公开 |

初期不以“所有格式都能一键生成”“人人都能搭复杂流程”作为可用性承诺。首页可以介绍模型能力，但不把选择模型变成普通用户完成任务的必经步骤。

## 3. 对象模型：项目是画布，资产是共享层

```text
User / Workspace
  ├─ CanvasProject（一个项目对应一张主画布）
  │    └─ CanvasNode / CanvasEdge（视觉布局与资产引用）
  ├─ Conversation / Message（可独立存在，可关联或转为项目）
  ├─ WorkflowDefinition / WorkflowVersion / WorkflowRun / NodeRun
  ├─ Prompt / PromptVersion
  ├─ Skill / SkillVersion
  └─ Asset / AssetVersion / Folder / AssetLink
```

**项目＝画布**是用户心智和首版产品约束：新建项目即新建一张主画布，项目列表即画布列表。后台可把项目元数据、画布布局和访问权限分表存储，但不得在产品中出现另一个需要用户管理的“项目容器”。未来若单张画布过大，再研究分区或子画布，不先增加一级概念。

**资产不是画布节点的副本。** 文件字节与结构化内容保存在资产系统，画布节点保存 `AssetRef` 和展示位置。一个 Agent 产物可同时出现在“Agent 来源”视图和某个项目画布，移动用户文件夹也不改变来源。工作流运行记录和对话历史同样是独立对象，通过资产引用相连。

建议基础引用为 `AssetRef = { assetId, versionId }`。每份资产记录所有者、来源（个人上传／Agent／画布／工作流）、所属文件夹、类型、版本、创建时间、派生输入和权限。复制到画布默认是**引用**，如需生成独立副本则明确提供“复制为新资产”。

### 3.1 三条关键生命周期

1. **Agent 会话 → 项目**：用户从历史会话点“创建项目”，系统新建画布，允许选择本次会话的附件和已生成产物，将其作为资产引用排布在画布；原会话、原文件夹和来源记录保留，之后可继续关联该项目。普通聊天文字不会逐条自动变成云盘文件，用户可选择将某条回复保存为文档资产。
2. **工作流 → 资产 → 画布**：运行可不绑定项目而独立开始；入参可从个人资产、Agent 资产或画布项目选择。每个阶段产物写入资产库并标明来源运行。用户按需将关键产物加入画布；若启动时指定了项目，关键产物可按工作流的展示规则自动出现在该画布，其他候选留在资产库和运行详情中。
3. **画布／资产 → Agent 或工作流**：用户在 Agent 或工作流输入框里选择某张画布、节点、文件夹或单个资产作为上下文。跨模块只传引用与授权范围，不传一份不可追踪的临时文本副本。

## 4. 信息架构与首页

建议侧栏保留六个明确入口：**首页、项目、Weavl Agent、市场、工作流、资产**。现有“预设”移入工作流；画布通过“项目”列表进入。市场仅包含“提示词、Skill、我的创作”，不混入工作流商品；工作流的官方范例放在工作流内的“发现／官方工作流”。

首页按首次用户的理解顺序安排：

1. **Agent 引导首屏**：一句具体的价值主张、可直接输入的对话框、上传入口与 3 个可真实执行的示例任务。提交后进入独立 Agent 会话，而不是默默跳入画布。
2. **模型能力介绍**：按“擅长什么／产出什么／适合何种任务”展示已接入的文本、图像、视频、音频和文档能力；供应商名称与参数放进详情。尚未可用的能力明确标注，不与已可用能力混排。
3. **功能介绍**：用一份真实素材串起“Agent 生成 → 资产保存 → 画布精修 → 工作流批量复用”，解释平台连贯性。
4. **作品案例**：展示可打开的真实或明确标注为示例的图文、视频、演示文稿及 IP 交付案例，附输入类型、关键步骤和最终成果，不使用未经验证的使用量或效果数据。
5. **继续工作**：最近会话、最近项目画布、待审核工作流运行，帮助老用户直接回到任务。

视觉目标是高端、克制的创作工作室：大尺寸真实作品预览，清晰排版和有限的强调色；动效服务于任务状态与内容切换。工作台应把预览、输入和当前产物放在装饰效果之前。

## 5. 项目＝画布：自由创作工作台

### 5.1 首期功能

- 新建、重命名、打开和保存项目画布；项目卡显示封面、最近编辑时间和代表性产物。独立项目必须有稳定 ID，不可像当前原型一样全部跳到同一个 `/canvas`。
- 基础节点支持文本、图片、视频及文件／结果卡；可拖放、连接、预览、引用资产、调用与当前节点相关的 Skill。
- 资产面板可从“我的资产、Agent 产物、工作流产物、当前项目”筛选并拖入画布；拖入时保留原资产的来源和版本。
- 画布右侧 Weavl Agent 抽屉读取当前项目和用户选中的节点／资产，经过明确授权后可添加、修改或生成节点内容。每次改动可撤销并标明由 Agent 操作。

### 5.2 扩展节点能力的分类

**资产节点**负责呈现某种文件：Word、PPT、PDF、图片、音频、视频。各类型先拥有统一的引用、缩略图、预览与导出能力，再按质量和需求增加编辑器。**操作节点／工具**负责产生或转换内容：生成 PPT、解析 PDF、数字人口播、视频剪辑等。数字人生成主要是操作能力，输出通常是视频资产；不必因为它叫“数字人”就发明一种与文件节点平级的永久文件格式。

首期节点注册需声明类型、可接受资产、输出类型、编辑／预览组件和可用 Skill；新接 Word 或 PPT 时不应改动所有既有节点逻辑。跨格式的生成依赖 Skill 或服务适配器，画布承担组织、确认和局部修改。

**验收**：用户从个人资产拖入 PDF、从 Agent 结果拖入脚本、从工作流结果拖入视频，在同一画布上看到三者的来源并能分别打开；刷新页面后布局、引用和版本不丢失。

## 6. Weavl Agent：独立对话与项目转化

### 6.1 界面与功能

独立 Agent 页采用持续对话的三栏逻辑：左侧历史会话／新建会话，中间消息、输入和产物卡，右侧按需显示引用资产或任务过程。它可以独立完成任务，不要求用户先创建画布。输入支持文字、附件、引用已有资产；用户可直接写提示词，也可选择市场中的提示词或 Skill 快速开始。

Agent 需展示它准备使用或已经使用的 Skill、所引用的资产、生成中的状态和最终产物。对于修改资产或启动高费用／有外部副作用的操作，界面要给用户可理解的确认与结果反馈。Agent 的“像 Codex 一样持续工作”在本产品中指**有历史、上下文、进度和可继续的任务**，不应只把普通聊天气泡换一个名称。

### 6.2 历史会话与资产

- 会话支持列表、搜索、重命名、归档、继续对话，并记录产物与已调用 Skill。
- 附件及生成的文件／结构化成果进入资产系统，在资产页“Agent”来源视图可检索；生成图片、文档和视频应作为独立资产，而不是只存在于消息内的临时 URL。
- 从任意历史会话“创建项目”时，可预览将加入画布的附件和产物，再创建项目画布；默认引用原资产版本，避免复制占用和来源断裂。
- 删除／归档会话不应暗中删除已保存资产或已创建项目中的引用；资产生命周期由资产页管理。

**验收**：用户在无项目状态下与 Agent 生成三版脚本，次日从历史会话找回，选其中一版创建项目；资产页“Agent”来源能找到三版，画布中仅出现选中的一版，来源和版本清晰。

## 7. 市场：提示词与 Skill

### 7.1 对象边界

**提示词 Prompt** 是可参数化的文本／多模态指令，包含使用场景、变量、示例输入输出、版本和作者。**Skill** 是可复用的方法包，可以包含指令、资源、工具调用和多个内部步骤；它可以被 Agent 使用，也可由画布操作或工作流节点调用。Skill 的规模不决定它是否是工作流。**工作流**另有显式节点、入参、运行状态、人工确认和重试机制。

市场首期设“提示词”“Skill”“我的创作”三个页签。官方条目可直接使用，用户可创建私有提示词和 Skill、试运行、编辑与版本化；公开上架需质量审核和权限规则，不与私有创作同时默认开放。提示词的“使用”将变量填入 Agent 输入；Skill 的“使用”打开适用入口并提示所需资产与权限。

首期 Skill 创建可从**说明、输入输出和允许调用的现有工具**开始，复杂脚本或第三方代码执行需要隔离环境与审核后再开放。市场卡片以实际示例、适用输入、输出类型和作者信息说明价值，不用模糊的“万能”“高转化”标签替代效果证据。

**验收**：用户创建一个私有口播改写 Skill 和一个带 3 个变量的提示词；在 Agent 中找到并使用两者；Skill 生成的脚本进入资产页，来源可追溯。

## 8. 工作流：编排器与表单式运行 WebUI

### 8.1 面向设计者：复杂节点编排

工作流定义包括名称、描述、版本、输入 schema、节点和连接、Skill／服务引用、输出 schema、关键产物展示规则、人工确认点及权限。节点分为输入、Skill／模型／API 调用、条件与循环、人工确认、资产输出等类型；节点编排器可以复杂，但发布前必须校验输入输出兼容、缺失配置、不可达节点和费用预估。

工作流定义可独立于任何项目创建、测试和发布。一次运行固定所用版本和输入资产版本。节点调用失败不覆盖旧产物，重试产生新记录；重新优化上游内容时，下游受影响节点应提示重新运行范围。

### 8.2 面向使用者：自动生成 WebUI

用户使用已发布的工作流时默认看到**表单式 WebUI**，而非编排节点图。表单由输入 schema 生成，支持文本、选择、数字、文件上传与“从资产选择”；文件字段能切换个人资产、Agent 产物和项目画布资产。填写后显示预计时间／费用范围与将产生的主要成果，再启动运行。

运行页以业务阶段展示进度。设计者可为每个节点设定 `hidden / summary / preview / review` 展示等级：内部处理不展示，关键节点展示核心产物，需审核的节点显示候选版本、依据与“采纳／修改后继续／重新生成”。用户的“优化”应明确修改哪份输入或产物，并保留旧版本；“重试”应说明从哪一节点开始、哪些下游将失效、可能发生的额外费用。高级用户可切到节点诊断视图查看详细输入输出与错误。

每一阶段性产物及最终产物都保存为资产，来源标注工作流、运行 ID、节点和版本。用户可在结果页选择“加入项目画布”“交给 Agent 继续修改”“放入文件夹”或“导出”；这些操作引用同一资产。若工作流在某项目画布中启动，可按展示规则自动把关键结果卡加入该画布，其余中间产物仅入资产库，防止画布拥挤。

**验收**：非设计者通过表单启动 IP 工作流，在定位和脚本两个节点审核候选并要求重做一版，最终把脚本交给 Agent 改写、把样片加入画布；各版本、费用和来源均能找回。工作流运行服务重启后仍可继续。

## 9. 资产：带来源和版本的云盘

资产页提供“全部、个人上传、Agent、工作流、项目画布、最近使用”来源视图，以及用户创建的文件夹树。来源视图是**智能筛选**，文件夹是用户自己的组织方式；一份文件移入“客户 A”文件夹后仍保留其“Agent 生成”的来源标签。

首期操作包括上传、批量选择、预览、搜索、按类型／来源／时间筛选、新建文件夹、移动、重命名、引用到 Agent 或画布、下载与回收站。资产卡展示文件类型、缩略图、当前版本、来源和使用位置。文件夹移动不改变资产 ID；在多个项目被引用的资产删除前给出使用提示。个人资产可从画布和 Agent 中直接选用，也可成为工作流入参。

资产应覆盖文件和结构化成果：脚本、定位方案、问卷数据、PPT 大纲都不应仅作为聊天文本或节点内字符串存在。大文件使用对象存储，元数据、版本和引用关系单独存储；预览失败不影响原件和运行历史。

**验收**：用户建“张总 IP”文件夹，上传 5 份资料，引用其中 2 份给 Agent、3 份给工作流；生成后的脚本与样片在相应来源视图可见，也可移入同一文件夹，来源与引用关系仍保留。

## 10. 跨模块契约与首期技术要求

| 契约          | 首期必须明确的规则                                                            |
| ------------- | ----------------------------------------------------------------------------- |
| 资产引用      | 所有模块使用稳定 `AssetRef`；明确版本；权限校验在服务端完成                   |
| 项目画布      | 项目有稳定 ID、持久化布局与资产引用；新建项目不复用同一默认画布               |
| 会话转项目    | 从历史会话选择产物建立画布引用，保留原会话与资产来源                          |
| Prompt／Skill | 独立 ID、作者、可见范围、版本、输入输出与使用记录                             |
| 工作流运行    | 定义版本与输入快照固定；节点状态、候选产物、人工决定和实际费用持久化          |
| 外部能力      | 模型与供应商通过适配器接入；记录请求 ID、超时、取消支持和重试策略             |
| 画布同步      | Agent／工作流通过服务端命令和资产事件更新画布引用，不能依赖用户浏览器一直打开 |

推荐先使用模块化单体、数据库、对象存储和任务队列交付这些契约。复杂流程编辑器可逐步增加节点类型；工作流引擎的持久化和资产版本应先于公开的“一键自动化”承诺。

### 10.1 交付优先级

| 优先级          | 范围                                                                                                                                     | 完成判据                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| P0 · 平台贯通   | 真实 Agent 会话、项目画布持久化、个人与来源资产、文件夹、基础 Prompt／Skill 私有创建和使用、一个表单式真实工作流、关键节点审核与结果共享 | 阶段 A、B 的旅程由真实数据完成；刷新或服务重启后内容和运行仍在 |
| P0 · 首页可信   | Agent 主入口、已接入模型介绍、功能说明、可追溯作品案例                                                                                   | 首页承诺的每个主操作可进入实际可用流程；演示内容明确标注       |
| P1 · 格式与定制 | Word／PPT／PDF 专项生成与预览增强、数字人供应商接入、更多视频能力、企业 API／Webhook 配置、工作流高级控制节点                            | 新能力遵循同一资产与运行契约；不需要为每种格式复制一套系统     |
| P2 · 生态       | 公开 Skill／提示词投稿、审核、分发和商业化；跨团队模板供给                                                                               | 有质量评测、权限、版本和售后处理机制后开放                     |

P0 不要求自建模型或完整 Office 编辑器。若首单必须使用数字人，可以把一个受控的数字人适配器提前纳入 P0；这属于试点交付范围调整，不改变能力扩展方式。

**迁移顺序建议**：① 定义资产、项目画布、会话、Prompt、Skill、工作流的共享契约；② 建立资产库和持久化项目画布；③ 打通 Agent 真实会话与“会话转项目”；④ 将现有预设移为工作流定义并提供表单式运行；⑤ 实现市场创作与更多节点／格式。可并行打磨视觉，但首页案例只能展示已能真实完成或明确标注为演示的内容。

已有工作区的界面文件可能有未提交修改；本 PRD 不要求在讨论阶段直接重命名路由或覆盖正在进行的界面工作。

## 12. 阶段验收与观察指标

**阶段 A：内容贯通。** 用户上传个人资产 → Agent 生成脚本 → 资产页找回 → 从会话新建项目 → 画布引用同一脚本。重点看首次成功率、找回时间和重复上传次数。

**阶段 B：工作流贯通。** 用户用表单运行一个真实业务工作流 → 在关键节点审核与重试 → 阶段产物入资产 → 最终产物加入画布／交给 Agent。重点看任务完成率、人工接手次数、恢复时间、真实成本与产物采纳率。

**阶段 C：扩展验证。** 在不修改资产和运行核心契约的前提下，增加一种非 IP 的流程或新资产类型。重点看新增能力需要改动多少核心代码，以及原有项目是否仍可正常使用。

不在缺少试点基线时预设具体提升百分比。首批客户的现有制作时间、返工次数与成本需要先记录，再确定付费推广门槛。

## 13. 待讨论的产品决策

| 问题                             | 当前建议                                                         | 为什么需要讨论                        |
| -------------------------------- | ---------------------------------------------------------------- | ------------------------------------- |
| Agent 产物何时进入资产库？       | 附件和生成文件自动保存；普通对话文字由用户主动保存               | 控制云盘噪声和存储成本                |
| 历史会话创建项目时加入哪些内容？ | 允许预览并勾选产物与附件，默认推荐关键成果                       | 避免整段会话自动铺满画布              |
| 工作流运行是否必须指定项目？     | 不必须；无项目时结果先进个人资产，之后可加入画布                 | 保持工作流和 Agent 独立使用           |
| 市场何时允许公开发布？           | 首期私有创建与官方精选；公开上架经过质量与权限规则后开放         | 防止低质量条目和不可信 Skill 破坏体验 |
| Word／PPT／PDF 首期做到哪一步？  | 先支持资产化、预览、引用和有质量保证的少数生成路径；深度编辑分期 | 避免“支持格式”被误解为完整办公套件    |
| 工作流关键产物默认放画布吗？     | 项目内启动时按工作流展示规则自动放关键结果；其他结果留资产库     | 保持画布清晰且不遗漏重要成果          |
| 首个 IP 工作流具体交付标准？     | 以真实客户问卷、脚本、样片和审核流程共同定义                     | 决定工作流节点、供应商与质量门槛      |

本文是讨论基线。定位确认后，下一份文档应把每个页面写成可设计的交互规格，并为共享对象、运行状态和资产事件形成工程契约。

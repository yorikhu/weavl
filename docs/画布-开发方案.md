# 织光画布 · 开发方案 v2

> 依据：立项书 §2.1（"以多模态创作画布为资产中心"）、产品设计 v0.1（§3 核心判断 + §5 用户旅程）、LibTV 画布调研、当前 v25 实现。
> 版本：v2 · 2026-09-04 · 状态：方案待评审
>
> **v2 变更**：补齐三个基础节点（文本 / 图片 / 视频）的统一交互模型与编辑范式，明确「原卡片不动 + 底部追加编辑栏」为通用约定；记录 v7→v25 的关键里程碑。

---

## 0. 一句话定义

**画布是织光的工作台** —— 用户在画布上自由组织内容资产、配置生成流程、调用预设任务。**预设是入口，画布是空间，节点是单元，AI 在背后跑任务**。

- 用户操作永远是业务动作（采纳/换一批/拖动/连线/上传），**不**碰节点配置
- 画布 = 资产 + 任务过程 + 协作面板的**统一空间视图**
- 预设任务跑起来 → 画布自动生长出流程图（**自动铺**）
- 用户在画布上自由堆节点 → 手动跑任务（**手动跑**）
- 用户在底部对话框说话 → AI 自动生成节点和连线（**V1.x Agent 驱动**）

## 1. 设计边界（与立项书/产品设计对齐）

### 1.1 织光 vs LibTV

| 维度       | LibTV                          | 织光                              | 决策                   |
| ---------- | ------------------------------ | --------------------------------- | ---------------------- |
| 节点类型   | 通用能力（脚本/三视图/生视频） | 业务能力（按能力类型着色 4 色）   | 织光更面向"业务"       |
| 用户身份   | 专业影视创作者                 | 普通运营/个人 IP/代运营           | 织光更"轻"             |
| 工作流方式 | 用户手动搭（100% 自由）        | **双轨**：手动堆 + 预设跑完自动铺 | 织光降低门槛           |
| Agent 驱动 | 已支持（Skill 接口）           | V1.x 再做                         | 织光 MVP 先做手动+自动 |
| 商业画布   | 是                             | 否（个人空间/团队空间）           | 织光更"私有"           |
| 预设       | 无（Skill 替代）               | 核心单位                          | 织光独有               |

### 1.2 MVP 边界（v0.1 必须，v1.x 再加）

**MVP 包含**：

- ✅ **3 类基础节点**：文本 / 图片 / 视频（通用容器，与业务能力节点并存）
- ✅ **Card 业务节点**：260px 宽、大圆角矩形、字段表（沿用 v4）
- ✅ **基础节点交互范式（v22 通用约定）**：
  - 默认态（拖拽态）= 标题在卡片上方 + 卡片 + 左下角 chip 区
  - 双击进入**编辑态** = **原卡片完全不动** + 底部追加编辑栏
  - 编辑态标题可改名（透明无边框 input，focus 才显示微弱底色）
  - 点击外部自动保存退出（视口不动）
- ✅ **图片节点（v25）**：
  - 默认态左下角双 chip：**图生图**（点击直接选图写回节点）+ **图片高清**（占位）
  - 编辑栏：标签行（参考/标记/风格）+ 输入框 + 参数行（模型 / 比例·画质·张数 / ⚡token / 发送）
- ✅ **视频节点（v25）**：
  - 默认态左下角：`尝试：↻` + 三个能力 chip（5 分钟超长视频 / 首尾帧生成视频 / 首帧生成视频）
  - 编辑栏：标签行（参考/标记/特效/角色库/运镜）+ 输入框 + 参数行（模型 / 文生视频 / 比例·画质·时长·张数 / 文档 / 文字样式 / 分享 / ⚡token / 发送）
- ✅ **文本节点（v7）**：contentEditable + 浮动富文本工具栏 + 双击进入编辑
- ✅ **双击节点聚焦编辑**（参照 LibTV 剧本节点）：
  - 双击节点 → 画布 zoom 到 2x 并把节点居中（setCenter，320ms 动画）
  - 顶部浮出 **FloatingToolbar**（fixed top 64px）：字体/字号/字号 select、加粗/斜体/下划线/删除线、颜色 picker、背景高亮、左/中/右对齐、缩进/列表、链接、清除格式
  - **不**再使用左侧完成/取消悬浮面板（v10 移除）——点击外部自动保存退出
  - TextNodeEditor 复用 styles.textNode 框形，标题 input 在头部，body 是 contentEditable（自动聚焦 + 光标到末尾）
  - **编辑态不做高亮**（v18：边框回归中性 #27272c）
  - **不**保存和恢复视口（v11：退出编辑位置和大小都不变）
  - 节点选中态的 nodeToolbar 在编辑时隐藏
  - IME composition 期间 guarding `composingRef`，避免中文输入重复触发（v7）
  - DOM 直接管理 contentEditable 文本（buffer 只在 commitEnd/blur 时同步，绕过 React 重渲染的光标重置）
- ✅ 节点库（固定能力节点）
- ✅ 选中节点浮出 NodeToolbar（按 kind 切换工具胶囊）
- ✅ 连线（smoothstep 实线弧形，可选 label）
- ✅ 节点操作：拖动、连线（拖出 + 拖空白新建节点）、删除、缩放/平移（mac 触控板双指平移）、MiniMap
- ✅ 底部 chat-bar：图片缩略位 + 输入框 + 模型选择器 + 发送按钮（Agent 占位）
- ✅ 底部工具图标：资产管理/配置/用户/连线/100% 缩放
- ✅ 顶部栏：返回 / 画布名 / 画布切换 / 分享 / 设置 / 积分 / 头像
- ✅ 空态、加载态、错误态
- ✅ **右键画布添加节点**：玻璃质感菜单（文本/图片/视频）
- ✅ **底部工具栏「+」添加**：向上弹菜单（基础 3 项 + 业务能力入口）

**MVP 不包含**（v1.x）：

- ❌ Agent 自动生成节点（chat-bar 仅占位）
- ❌ 连线双击编辑
- ❌ 富文本渲染（编辑面板写内容，节点态展示纯文本；V1.x 接 Markdown 预览）
- ❌ AI 重写按钮真实能力（占位 alert）
- ❌ 多画布（同一工作区多画布）
- ❌ 节点资产库/自定义能力
- ❌ 多人协作
- ❌ 节点间连线的复杂条件（当前只是视觉连接）
- ❌ 画布版本历史/分支对比
- ❌ 模板分享链接
- ❌ 实际生图/生视频 API（v25 编辑栏只把状态写回节点 data；按钮发送是 placeholder）

### 1.3 复用现有成果

- 共享契约 `packages/shared`：**已含** TemplateManifest / Step / ConfirmationGate / CandidateArtifact / ContentPackage / RunView
- API `/api/templates`、`/api/runs`、`/api/runs/:id/decide`、`/api/runs/latest/_pick`：**已实现**
- 画布 v25 实现：**基本就位**，3 类基础节点 + Card 业务节点均可使用；后续补**稳定性+测试+数据联通**

## 2. 技术架构

### 2.1 路由

```
/canvas                → 默认画布（无 projectId，未来加 [id] 维度）
/canvas/[projectId]    → 项目内画布（V1.x）
```

MVP 用单画布路由；projectId 维度等「项目详情页」做时一起加。

**数据来源**：

| 节点来源           | 触发时机                          | 数据映射                                       |
| ------------------ | --------------------------------- | ---------------------------------------------- |
| 手动加（节点库）   | 用户点底部"+ / 节点库"            | 业务能力节点映射                               |

### 2.4 与后端的接口（已有/需要新增）

**已有**（后端已实现）：

- `GET /api/runs/latest/_pick` → 最近 run（画布启动加载用）
- `GET /api/templates` → 模板列表（节点库"我的预设"扩展用）
- `POST /api/runs` + `POST /api/runs/:id/decide` → 任务执行与决策（V1.x 手动跑用）

**V1.x 需要新增**：

- `POST /api/canvases` 创建画布
- `GET /api/canvases/:id` 拉取画布（节点+边）
- `PATCH /api/canvases/:id` 自动保存（debounced 1s）
- `POST /api/runs/from-canvas` 从画布节点编排生成任务
- `POST /api/assets/upload` 内容包产物回流入素材库
- `POST /api/image/generate` 图片生成（节点发送按钮触发）
- `POST /api/video/generate` 视频生成（节点发送按钮触发）

**MVP 仅用现有接口，不开新端点**。canvas 节点编排**暂存 localStorage**（用户不清浏览器即可恢复）。

## 3. 组件规格

### 3.1 CardNode（业务节点）

```tsx
interface CardNodeData {
  nodeKind: "card";
  kind: NodeKind; // "llm" | "image" | "video" | "output"
  title: string;
  category: string;
  fields: { label: string; value: string }[];
  isGate?: boolean;
}
```

视觉：大圆角 14px、宽 260px、深背景 #161618、左上角 accent 高亮条（按 kind 着色）、连接 handle 在左/右。

### 3.2 基础节点通用约定（v22 沉淀）

> **「原卡片不动 + 底部追加编辑栏」**：默认态组件和编辑态共享同一份卡片组件（`ImageCardStatic` / `VideoCardStatic`）。进入编辑时卡片大小/位置/内容/chip 都不变，只是在下方长出编辑栏。

- **卡片本体** = 标题（带可改名 input）+ 圆角卡片 + 左下角 chip 区 + 左右连接点
- **编辑栏** = 标签行 + 输入框 + 参数行（居中，宽度大于卡片）
- 标题样式：默认态 span，编辑态 input（透明无边框）
- 点击外部 = 退出编辑 + 自动保存（commitEdit 路由 `nodeKind` 走对应 commitImageEdit/commitVideoEdit/saveEdit）

### 3.8 NodeLibraryModal

固定 4 个能力（无需动态生成）：

- 故事脚本生成（Card / LLM）
- 角色三视图（Image / 280×180）

## 5. 性能与边界

| 指标             | 目标                       | 实测方法                       |
| ---------------- | -------------------------- | ------------------------------ |
| 首次加载（空态） | < 500ms                    | Next.js dev 启动后冷加载       |
| 加载最近任务     | < 1s                       | API 响应 + 节点渲染            |
| 节点数上限       | 单画布 200 节点不卡        | React Flow 性能边界约 500 节点 |
| 缩放范围         | 0.3x - 2.5x                | fitView 默认适配               |
| 移动端           | 暂不支持（小屏画布体验差） | 后续可加 responsive 布局       |

**性能陷阱**：

- 节点 > 100 时，`onSelectionChange` 频繁触发 → debounce 选中态更新
- chat-thumb 大图（>5MB）渲染慢 → 限制单图最大 1MB（FileReader 前压缩）
- contentEditable 在 IME 期间 React setBuffer 会重置光标 → **绕过**：`composingRef` guarding + DOM 直接管理文本，commitEnd/blur 才同步 buffer

### 12.3 校验规则

| 场景                     | 校验结果                           |
| ------------------------ | ---------------------------------- |
| 拖到源节点自身           | 不可连                             |
| 拖到已存在同源同目标的边 | 不可连                             |
| 拖到 disabled 节点       | 不可连                             |
| 拖到 pane 空白           | 弹「引用该节点生成」菜单（可新建） |
| 拖到任意其他节点         | 可连（自动连上）                   |

### 12.4 实现要点

1. **监听悬停**：用 `onNodeMouseEnter/Leave` 实时跟踪当前 hoverId，结合 `connectStartRef`判断是否在拖线中 + 是否是合法目标节点。
2. **CSS 三态路径**：通过自定义 edge 类型包装 SVG path，加 `.preview-connectable / .preview-blocked` 类切换样式。
3. **SVG path 描绘动画**：用 stroke-dasharray + stroke-dashoffset（值等于 path 长度）做 320ms ease-out 描绘。
4. **目标节点高亮**：合法节点加蓝色 outline + scale(1.02)；非法节点保持灰色虚框；松手成功后立即闪光。
5. **失败反馈**：添加临时边 → 200ms 后从 edges 中移除；用 toast 组件展示「无法连接：原因」。

### 12.5 验收清单

- [ ] 拖线悬停合法节点：节点边框变蓝 + 蓝色发光 + 预览路径变蓝实线
- [ ] 拖线悬停源节点自身：预览路径变灰虚线 + 末端 ⊘
- [ ] 拖线悬停 disabled 节点：节点 dashed 边框 + 预览路径灰虚
- [ ] 松手连成功：连线滑入 320ms + 目标节点闪光 400ms
- [ ] 松手失败：连线变红 + shake + 自动消失 + toast 提示
- [ ] 松手 pane 空白：弹「引用该节点生成」菜单

## 13. v34 图片节点编辑态：画布可缩放 + 编辑栏固定屏幕 40%

### 13.1 背景与目标

**现状（v33）**：

- 双击图片节点进入编辑态后，整个画布被 `nowheel` 容器捕获，触控板双指移动会被 React Flow 的全局 `panOnScroll` 拦截，**画布完全不可缩放/平移**。
- 编辑栏（图片下方那条参考/标记/风格/输入区/模型参数条）宽度写死 480px、位置写死"图片正下方 24px"，跟画布缩放完全无关。

**目标（v34）**：

- 进入编辑态后，**画布恢复可缩放与可平移**（触控板双指/滚轮/缩放控件/小地图全部正常工作）。
- 编辑栏**水平居中对齐当前编辑的图片节点**（不是屏幕居中）：编辑栏水平中线 = 当前编辑节点在屏幕上的视觉中心 x 坐标（`node.x + node.width × zoom / 2` 投影到视口坐标），宽度 = **屏宽 × 40%**，位置 = **屏幕底部 + 距底 16px**。
- 编辑栏**不参与画布缩放**——即使画布放大到 250%，编辑栏在屏幕上的物理尺寸始终是屏宽 40%；但其水平 x 位置会跟随当前编辑节点随画布平移/缩放移动（节点动它跟着移）。
- 编辑栏**永远在屏幕内**：当节点中心靠近屏幕左/右边缘时，编辑栏不溢出屏外，而是贴着对应边沿留 16px 内边距。
- 退出编辑态（点击外部 / ESC / 切换节点）后，编辑栏消失，画布保留当时的视角。

### 13.2 视觉规则

| 元素                                | 行为                                                         | 备注                         |
| ----------------------------------- | ------------------------------------------------------------ | ---------------------------- |
| 画布背景 / 网格 / 缩放控件 / 小地图 | 完全可用，触控板双指滚动=平移，捏合=缩放                     | 不再被 `nowheel` 屏蔽        |
| 当前节点卡片                        | 跟随画布缩放（保持原行为）                                   | 用户缩放时能看到节点变大变小 |
| 连线                                | 跟随画布缩放                                                 | 不变                         |
| 编辑栏                              | **固定屏幕底部居中**，宽 = `vw × 0.4`、距底 24px、内容自然高 | 不参与画布缩放               |
| 标题栏                              | 跟随画布缩放                                                 | 不变                         |

### 13.4 实现要点

1. **去掉 `nowheel` 容器拦截**：删除 `ImageNodeEditor` 外层 `<div className={...nowheel}>` 的 className（TextNodeEditor 的 `nowheel` 也已无需保留文本框内滚轮，但为了文本编辑体验可保留，本期不动）。
2. **编辑栏脱离 React Flow viewport**：将编辑栏从 `ImageNodeEditor` 内 React Flow 渲染树中抽出，改挂到 `CanvasInner` 的顶层，用 `position: fixed; bottom: 16px; width: 40vw; max-width: 720px; min-width: 320px;` 定位。
   - **x 坐标算法**：通过 `useStore` 订阅当前 zoom 与 viewport；用 `screenToClientPosition`/`useReactFlow` 的 `flowToScreenPosition`（v12 API）算出当前编辑节点的**屏幕中心 x** = `node.position.x + nodeWidth/2` 投影到屏幕坐标。
   - 编辑栏 `left` = `Math.max(16, Math.min(window.innerWidth - panelWidth - 16, centerX - panelWidth/2))` —— 永远不出屏。
   - 用 `transform: translateX(${left}px)` 而非 `left` 直接设置，避免 React 重复 reflow（用 `useMemo` 缓存计算结果）。
3. **状态联动**：`editingId` 仍是 React 状态（来自 `EnterEditContext`），`ImageNodeEditor` 改为只渲染上半部分（标题 + 原卡片复用 `ImageCardStatic`）；编辑栏改为 Portal（`createPortal(..., document.body)`），由 `CanvasInner` 根据 `editingId` 决定是否挂载。
4. **数据来源**：编辑栏内表单（prompt/ratio/quality/count/model/imgUrl）改为读 `imageEditStateRef` 引用并通过 `commitImageEdit` 写入；当前节点 id 从 `editingId` 取，原 `ImageNodeEditor` 的内部 `useState` 字段上移到 `CanvasInner`，作为编辑栏受控组件的 state。这样退出编辑态时值仍归零（commit 由外部保存）。
5. **图片预览与缩放**：图片节点本体保留 React Flow 节点坐标（`position` 不变），用户缩放画布时图片本身跟着变大变小——这就是用户要的"缩放时上面图片变大小"，而编辑栏不跟着变。
6. **最小可缩放/平移测试**：进入编辑态后，触控板双指移动应能平移画布；捏合应能缩放；滚轮 + Ctrl 应能缩放；缩放控件 + - 应能用；MiniMap 拖动应能用。
7. **退出编辑态**：点击其他节点 → 自动 commit + 切到目标节点编辑态；点击画布空白 → commit 当前并关闭编辑栏；按 ESC → commit + 关闭。

- [ ] 编辑栏宽度 = 屏宽 × 40%；距屏底 16px；水平中线对齐当前编辑节点的屏幕视觉中心
- [ ] 画布放大到 200% 时：图片节点视觉变大 1 倍，编辑栏视觉尺寸**不变**，但 x 位置跟随节点移动

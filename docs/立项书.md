# Weavl 织光项目立项书

## **一、项目概述**

**项目名称：** Weavl 织光

**项目类型：** 面向内容经营场景的 AIGC 业务交付平台

**拟解决的问题：** 当前 AIGC 工具已显著降低内容生成门槛，但用户仍需在“选模型、写提示词、反复生成、人工筛选、跨工具拼接、审核、发布、复盘”之间来回切换。Weavl 的目标不是再提供一个生成入口，而是将这些环节沉淀为可复用、可调整、可交付的“业务预设（Preset）”，帮助用户完成一次完整的内容经营任务。

**核心判断：** AIGC 的下一阶段竞争不在于“谁能生成”，而在于“谁能稳定地帮助特定用户完成业务结果”。Weavl 应从通用生成平台转向“预设驱动的内容运营工作台”：以多模态创作画布为资产中心，以轻量工作流为执行引擎，以表单和对话为用户界面，以人工确认节点保障质量，并逐步连接发布与数据反馈。

## **二、市场背景**

### **1. AIGC 已从技术尝鲜进入应用分层阶段**

生成式 AI 已具备广泛用户基础。截至 2025 年底，中国生成式人工智能用户规模已达 **6.02 亿**，普及率为 **42.8%**；而在 2024 年底，已有 31.0% 的生成式 AI 用户使用其生成图片或视频。用户已不再只把 AI 用于问答，而是在主动使用它完成多模态内容生产。

来源：[CNNIC《第57次中国互联网络发展状况统计报告》解读](https://www.digitalchina.gov.cn/2025/xwzx/qwfb/202602/t20260209_5283123.htm)、[CNNIC《第55次中国互联网络发展状况统计报告》](https://www.cnnic.net.cn/NMediaFile/2025/0117/MAIN173710689576721DFTGKEAD.pdf)

市场供给侧也正在成熟：模型能力、多模态生成、视频生成、数字人、脚本生成、内容理解和自动剪辑正快速商品化。用户对“生成一张图”“生成一段视频”的惊喜感会持续下降，而对交付速度、品牌一致性、内容合规、平台适配和经营效果的要求会上升。

因此，AIGC 产品会出现三层分化：

| 层级       | 用户购买的能力           | 典型产品形态                  | 竞争特征                   |
| ---------- | ------------------------ | ----------------------------- | -------------------------- |
| 基础生成层 | 模型、算力、单次生成     | 文生图、文生视频、模型 API    | 能力趋同、价格竞争强       |
| 创作工具层 | 画布、模板、编辑与素材   | 创作社区、剪辑台、WebUI       | 易获得，但用户仍需完成整合 |
| 业务交付层 | 可发布、可复盘的业务成果 | 行业工作流、运营系统、AI 员工 | 更靠近预算与留存，壁垒更高 |

Weavl 的机会应放在第三层，而不是与基础生成和通用创作工具正面竞争。

### **2. 内容经营的真实瓶颈不是“没有素材”**

以小红书、抖音等内容平台为例，内容生产的难题通常包含：

- 不知道做什么选题、如何匹配账号定位；
- 有商品图、品牌资料、过往素材，但无法快速组织成可发布内容；
- 图片、文案、脚本、视频、封面和发布配置分散在多个工具中；
- AI 单次产出不稳定，仍需反复抽卡、筛选、编辑和人工判断；
- 审核、违禁词、品牌调性、平台规格与发布节奏不可忽略；
- 内容发布后缺少数据回流，下一次创作仍然从零开始。

这决定了 AIGC 在内容运营中的价值，不能只按“生成次数”衡量，而应按“任务完成率、交付时长、发布率和复用率”衡量。

## **三、商业机会**

### **1. 从“创作工具”转向“内容经营操作系统”**

Weavl 的商业机会来自一个未被充分满足的中间层：

> 用户不想学习复杂工作流，也不满足于只获得零散素材；他们需要的是可控地完成一项内容业务任务。

例如，电商商家不是想要“十张商品图”，而是想要一套适用于小红书种草或抖音带货的内容；个人 IP 团队不是想要“一个视频模型”，而是想要从策划、脚本、Demo、客户确认到正式交付的连续流程。

这符合“待完成任务（Jobs to be Done）”理论：用户雇佣产品并非为了使用某项技术，而是为了在具体情境下取得进展。Weavl 所服务的任务可以被定义为：

- 把商品资料转化为可发布的种草内容；
- 把一个 IP 方向转化为可确认的视频样稿；
- 把品牌资产转化为持续、统一的账号内容；
- 把一次成功创作沉淀为团队可复用的运营 SOP。

### **2. “预设”是产品化的关键单位**

Weavl 不应将 Skill、模型、节点或 Agent 直接作为主要产品单位，因为它们对普通用户而言过于技术化，且难以保证稳定交付。

Weavl 的核心单位应是**预设（Preset）**：

> 一个围绕特定业务目标设计的、可输入素材、可执行生成、可人工确认、可输出发布物、可复用迭代的内容生产方案。

预设不是单一 Skill，也不是暴露给用户的流程图。它应包含：

| 组成         | 用户可感知的价值                                   |
| ------------ | -------------------------------------------------- |
| 业务目标     | “生成小红书商品种草内容”，而非“调用文生图节点”     |
| 轻表单与对话 | 用业务语言填写商品、受众、调性、渠道等信息         |
| 素材消费规则 | 自动调用画布、品牌库或外部导入的图片、视频、文档   |
| 执行工作流   | 在后台编排文案、图片、视频、审核、合成等能力       |
| 人工确认点   | 在选题、脚本、关键画面、成片等高风险环节可控介入   |
| 输出规范     | 输出符合小红书、抖音或交付对象要求的内容包         |
| 数据与版本   | 留下输入、过程、产物、修改与表现数据，支持复用优化 |

这使 Weavl 能把复杂的 Agent/Workflow 能力“产品化”，而不是要求每一个客户成为流程设计师。

### **2. 竞品结论**

竞争并不意味着 Weavl 没有机会，反而说明市场已验证三个事实：

- 用户愿意为垂类结果而非通用能力付费；
- 用户需要从素材到成品的连续体验；
- 预置能力比空白画布更容易被采用。

但 Weavl 不能简单复制“电商版生图”“短视频版 Agent”或“另一个工作流平台”。若只将多个模型放进同一画布，最终仍会陷入同质化；若直接开放复杂工作流，则会把配置压力转嫁给用户。

## **五、机会点与差异化策略**

### **1. 核心机会：降低“业务自动化”的心理和操作门槛**

Coze 等平台已验证工作流对复杂任务的适配性：其工作流可以将模型、插件、数据和逻辑按节点组织，并支持实时调试；但这种能力天然更面向具备配置意愿的创作者、开发者和企业用户。

来源：[Coze 低代码工作流说明](https://docs.coze.cn/guides_workflow)

Weavl 的产品机会不在于重新发明工作流，而在于完成以下转换：

> 从“用户搭建工作流”转换为“用户选择并运行业务预设”；
>
> 从“用户管理节点”转换为“用户管理素材、标准与确认”；
>
> 从“用户获得生成结果”转换为“用户获得可发布、可交付、可复盘的内容成果”。

### **2. 差异化定位**

**Weavl 织光 = 面向内容经营者的预设驱动式 AIGC 业务交付平台。**

其核心差异不应是某个模型更强，而应是：

1. **资产连续性**：画布不是终点，而是内容资产库。用户生成、上传、筛选的图文视频都可被后续预设调用。

2. **任务可交付性**：输出的不是孤立文案、图片或视频，而是围绕渠道规格、品牌要求和运营目的组织的内容包。

3. **人机协作可控性**：不追求“全自动替代人”，而是在风险高、审美强、业务判断重的节点保留人工审核与多次调试。

4. **标准方案可复制性**：官方将高频业务 SOP 封装为预设；高级用户和服务商可在受控范围内复制、调整、版本化，形成行业方案资产。

5. **结果数据可回流性**：从生成走向“生成—发布—数据—优化”的闭环，使下一次内容生产能够基于历史表现而非重新猜测。

### **3. 必须坚持的边界**

Weavl 不应承诺“用户点一下屏幕就完全替代运营”。更准确的价值主张是：

> 让一个普通运营者以更少的工具切换、更低的专业门槛和更短的时间，稳定完成 70%–80% 的标准内容生产工作；将人力集中于策略、审美、审核和关键决策。

这是更符合当前模型稳定性与平台内容风险现实的产品承诺。

## **六、目标用户画像与痛点**

### **用户画像一：中小品牌 / 电商商家运营者**

**特征：** 1–5 人运营团队；需要高频生产商品内容；缺少专业设计、文案、视频人员；预算敏感。

**典型任务：** 商品种草、上新、活动内容、带货短视频、店播素材、同城内容。

**核心痛点：**

- 商品资料多但内容产能不足；
- 不懂提示词、模型、剪辑和视觉风格；
- 图文、视频、文案分别在不同工具完成；
- 每轮内容都重新组织，无法复用爆款经验；
- 审核、违禁词、平台规格和发布节奏容易出错。

**最愿意付费的价值：** 节省人力与外包成本，提高稳定产能，并缩短从“有商品”到“可发布”的时间。

### **用户画像二：个人 IP / MCN / 内容工作室**

**特征：** 重视人设、调性和内容系列化；内容创意和客户确认频繁；多人协作。

**典型任务：** 账号定位、选题策划、视频脚本、Demo 提案、系列内容生产、客户交付。

**核心痛点：**

- 从提案到成片链路长，修改成本高；
- 人设、视觉、口吻难以持续一致；
- 客户确认发生在后期，导致返工；
- 素材、版本、意见分散在微信、QQ、网盘和剪辑工具中。

**最愿意付费的价值：** 提前产出可确认 Demo、减少返工、提高团队交付吞吐量。

### **用户画像三：代运营服务商 / 小型营销团队**

**特征：** 同时服务多个客户，有成熟但难以标准化的 SOP。

**典型任务：** 批量账号运营、客户周报、素材生产、内容排期、审核交付。

**核心痛点：**

- 优秀运营经验依赖个人，难复制、难培训；
- 客户品牌资产和权限管理复杂；
- 需要在效率与个性化之间取得平衡；
- 难对交付过程和成本进行管理。

**最愿意付费的价值：** 将服务 SOP 产品化，缩短新人培养周期，以更少人力服务更多客户。

## **七、产品定位与首期方案**

### **1. 产品定义**

Weavl 织光是一个以内容资产为基础、以业务预设为入口、以轻量工作流为引擎、以人工可控交付为原则的 AIGC 内容运营平台。

### **2. 首期 MVP 建议**

首期不宜同时覆盖“电商运营、个人 IP、短剧、全平台发布、数据分析”。建议选择：

**“商品素材 → 小红书种草图文 / 短视频 → 人工确认 → 发布内容包”**

原因：

- 输入明确：商品信息、卖点、图片、品牌资料；
- 输出明确：标题、笔记、封面、配图、短视频脚本/成片、话题和发布建议；
- 用户频率高，能快速验证留存；
- 人工审核必需，适合验证人机协作节点；
- 可自然扩展至抖音带货、品牌活动和代运营服务。

### **3. MVP 核心预设示例**

**预设名称：商品小红书种草内容包**

1. 用户填写商品、目标人群、卖点、价格带、品牌调性和发布目标；
2. 从画布或本地导入商品图、素材视频、品牌资料；
3. 系统生成选题与内容角度，用户选定或调整；
4. 系统生成文案、封面方案、配图/视频方案；
5. 在关键节点支持模型切换、提示词微调、多版本抽卡和人工筛选；
6. 完成违禁词、敏感表达、规格和品牌一致性检查；
7. 生成平台预览与发布内容包；
8. 第一阶段支持导出，平台开放能力和合规条件成熟后再接入授权发布；
9. 收集表现数据，形成下一轮选题与内容优化建议。

## **八、商业模式与增长验证**

### **1. 商业模式**

建议采用“免费试用 + 订阅 + 用量 + 企业服务”的组合。

| 收入方式          | 适用对象                     | 建议内容                                             |
| ----------------- | ---------------------------- | ---------------------------------------------------- |
| 免费层            | 新用户                       | 有限预设次数、基础素材空间、带水印或有限导出         |
| 个人 / 创作者订阅 | 个体运营者、IP 创作者        | 更多预设、高清导出、品牌资产、历史版本、基础数据建议 |
| 团队订阅          | 电商团队、工作室、代运营公司 | 多人协作、审批、客户空间、共享素材、权限和模板管理   |
| 用量计费          | 视频生成、高成本模型调用     | 按积分或执行次数收费，避免重模型成本侵蚀订阅利润     |
| 行业方案与服务    | 品牌、大商家、服务商         | 定制预设、私有品牌库、私有部署、工作流搭建与运营咨询 |

### **2. 获客与增长路径**

早期不要把“预设市场”当作第一增长引擎。市场需要供给质量、效果证明、交易与分发机制，冷启动难度较高。

更合理的增长顺序为：

1. **官方预设验证**：用 3–5 个高质量预设打通单一场景；

2. **标杆客户共创**：与商家、工作室或代运营服务商共建，获得真实案例；

3. **案例驱动获客**：以“节省多少时间、产出多少内容、发布率多少”的结果营销；

4. **团队协作带动扩散**：客户、审批者、设计/运营同事进入同一项目；

5. **认证预设生态**：在质量、版本、合规和结算机制成熟后，开放服务商/专家制作预设。

### **3. 必须验证的核心假设**

| 假设                                 | 验证方式             | 建议成功门槛                                 |
| ------------------------------------ | -------------------- | -------------------------------------------- |
| 用户愿意为“任务交付”而非单次生成付费 | 访谈、付费试点、预售 | 目标客户中有明确预算与复购意向               |
| 用户能接受表单+对话式预设            | 可用性测试           | 首次用户无需教学即可完成核心任务             |
| 工作流能减少工具切换和完成时长       | 对照测试             | 相比现有方式显著缩短从素材到可发布内容的时间 |
| 人工确认能提升质量但不破坏效率       | 记录节点停留与返工   | 审核节点集中于少数关键环节                   |
| 输出足以进入真实发布或交付           | 灰度试用             | 内容包完成率、采纳率、发布率持续提升         |
| 预设具有复用价值                     | 队列数据             | 用户在后续周期重复使用同一预设，而非只尝鲜   |

### **4. 首期北极星指标**

建议用：

> **每周完成并进入“可发布/可交付”状态的内容任务数**

配套指标包括：

- 预设启动率；
- 任务完成率；
- 从导入素材到可交付的平均时长；
- 每项任务的人工修改轮数；
- 生成内容的采纳率与发布率；
- 7 日 / 30 日预设复用率；
- 单个内容任务的模型成本与毛利；
- 团队内协作邀请率。

## **九、主要风险与应对**

| 风险           | 说明                                                 | 应对原则                                                 |
| -------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| 模型能力商品化 | 生成能力将被大厂快速追平                             | 不以单模型为壁垒，积累业务预设、资产、数据和协作关系     |
| 产出不稳定     | AI 生成仍会产生风格漂移、事实错误和审美失控          | 引入多版本筛选、质量检测、人工确认与可回退版本           |
| 平台发布限制   | 第三方平台 API、内容规则与授权能力可能变化           | MVP 先交付“发布内容包”，再以合法授权方式逐步接入         |
| 合规与版权     | 用户素材、生成内容、广告法、敏感词和模型授权均有风险 | 素材权属提示、审查能力、模型授权说明、企业隔离与日志留存 |
| 场景过宽       | 同时做电商、IP、短剧、代运营会导致产品失焦           | 首期只验证一个高频、可衡量、可闭环的任务                 |
| 工作流复杂度   | 功能越强，用户理解成本越高                           | 将工作流隐藏在预设后，仅向高级用户开放有限配置层         |

## **十、立项结论**

建议立项，但应以\*\*“垂直内容经营闭环”而非“泛 AIGC 平台”\*\*作为战略边界。

Weavl 的长期愿景可以是“让用户通过可复用预设完成内容运营”，但首期必须克制地验证一个具体任务：以商品内容运营为切口，证明用户愿意将素材交给 Weavl，并最终获得可发布、可复用、可优化的内容成果。

Weavl 最有价值的护城河不在于拥有多少模型、多少节点或多少 Skill，而在于能否持续沉淀：

- 行业业务 SOP；
- 用户品牌与内容资产；
- 人机协作中的质量判断；
- 已验证有效的预设；
- 内容发布后的经营反馈。

最终，Weavl 应从“帮助用户生成内容”，走向“帮助用户完成内容经营”。
